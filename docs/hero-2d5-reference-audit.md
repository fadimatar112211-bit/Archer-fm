# Archer FM — 2.5D Hero Reference Audit

Branch: `ranger-reference-work`

This document records verified findings from the current hero conversion work. It is a reference gate, not an approval of unfinished art.

## Non-negotiable visual source

Use the approved hero roster only:
- `assets/references/approved_all/hero_roster_concept.jpg`

Do not replace, redraw, recolor, crop, or invent a substitute for the approved reference. New in-game sprites must preserve the reference character identity.

## Shadow

- Runtime direction: 2D character sprites in the 2.5D arena.
- The walk test uses eight directions: `e, se, s, sw, w, nw, n, ne`.
- The test asserts four frames for every direction and checks each frame rectangle.
- The production arena painter is used for the captures at 800×450.
- The draw height is kept at 120 logical pixels; a temporary Shadow-only 210px experiment was reverted.
- Current automated Flutter analysis and unit/widget tests passed in workflow run `44887612199`.
- Android emulator smoke test and release APK build were still running at the last status check. Do not mark Shadow fully accepted until those jobs finish and the visual capture is reviewed.

## Flame — blocked; do not integrate the existing atlas as approved art

Inspection of `assets/heroes/flame/renders/atlases/walk_s.png` shows a small orange/brown character holding a flame/light source. This does not match the approved Flame Knight reference, which has:
- bright red/orange spiky hair,
- red scarf and red armor,
- gold shoulder/armor details,
- a large flaming sword.

The existing Flame atlas set has eight directional names, but its appearance is not reference-faithful. Having a technically valid 8-direction atlas is not enough. Do not wire this atlas into the playable hero until its art is replaced with a reference-faithful source.

The current Flame GLB visual captures also need correction: the arena captures show the model too small/poorly presented, and the yaw-0 close-up shows an underside/incorrect presentation rather than a clean readable hero view. This is a visual/presentation failure, not evidence that the reference has been met.

### Verified replacement source and build path

The repository already contains a procedural Flame identity profile in `tools/blender/hero_profiles.py`. It defines the Flame-specific red palette, spiky hair, short split cape, red/gold armour and scarf details, a large flaming greatsword, flame effects, and Flame attack/skill actions. This is the correct production path to evaluate before inventing or importing any new art.

The existing Flame atlas is still not approved. The profile has now been selected through `tools/blender/active_hero.txt` and the Blender render pipeline has been started to generate a fresh 8-direction set from that profile. The build must pass the renderer's transparent-frame, framing, animation-motion, rig and atlas validation gates, and its rendered previews must be visually compared with the approved roster before replacing the currently checked-in atlas.

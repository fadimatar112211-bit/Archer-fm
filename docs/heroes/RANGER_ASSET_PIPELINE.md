# Ranger full-production asset pipeline

This is the production render pipeline for the complete Ranger set, not a sample renderer.

## Reuse inventory
- The 4 legacy SVG sheets are retained in `assets/heroes/ranger/` as reference/fallback material. They are 4-frame 2D vector sheets, not the approved 2.5D Chibi production art.
- The legacy sprite clipping widget and timer-driven auto-fire logic are not copied. They do not support the agreed directional atlas, stable pivot, or the single `projectile_release` event.
- No rigged 3D source model or Blender scene was present in the audited legacy files. The renderer therefore requires the real production Ranger .blend source and refuses to fabricate substitute frames.

## Production source scene contract
Create `assets/heroes/ranger/source/ranger_source.blend` with:
- A complete Ranger model matching `RANGER_PRODUCTION_SPEC.md` (green hood/cloak with gold trim, silver-white hair, blue eyes, brown/green leather armor, quiver, signature green-energy bow).
- A production armature object named `Ranger_Rig`.
- Actions named `Ranger_Idle`, `Ranger_Walk`, `Ranger_Attack`, `Ranger_Death`.
- Active orthographic camera, fixed lighting, transparent-background-compatible materials, ground contact and consistent framing.
- Attack action must draw, aim, release, and recover; release frame must be authored and confirmed by animation review.
- Death action must settle and hold; idle/walk must loop cleanly.

## Full render
Use Blender's background mode with `tools/blender/render_hero.py` and `assets/heroes/ranger/source/render_config.json`. The configuration defines all 8 directions and all 4 states. It outputs every configured frame and a manifest. The default frame counts and timing in the config are production starting values and must be reviewed against the final authored Actions before a release build; do not alter them by creating disposable preview exports.

Blender supports PNG RGBA rendering and glTF animation export; see the official [Blender pipeline](https://www.blender.org/features/pipeline/) and [glTF manual](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html).

## Release gates
1. Verify the source model and rig exist and all named Actions are authored.
2. Review the complete eight-direction/four-state render for silhouette, consistency, pivots, clipping, and transparent edges.
3. Pack frames into atlas metadata without rotating frames; validate all referenced frame IDs and dimensions with `tools/validate_hero_assets.py`.
4. Verify exactly one authored `projectile_release` event per attack direction.
5. Measure the complete package size and runtime memory on target Android hardware.
6. Integrate into the selected runtime engine and run combat/transition tests.
7. Run the Android emulator acceptance suite and fix/retest all critical issues.

A renderer script and config are pipeline infrastructure; they do not mean the model or animation assets have already been produced.


## Procedural source scene builder

The repository now includes `tools/blender/build_ranger_source.py`. Run it in Blender background mode to generate the editable `ranger_source.blend` scene. It builds original stylized meshes and materials, a named armature, four editable animation Actions, an orthographic camera, and transparent-render settings. The model is deliberately authored as editable parts parented to bones, so the geometry, proportions, rig, and animation can be refined in Blender without recreating the scene.

The builder script is the reproducible source generator. The binary `.blend` is generated by running Blender; it is not represented as already generated by a GitHub text-file commit. After generation, inspect the model and every Action in Blender before running the complete renderer.


## Complete render → atlas → validation sequence

1. Generate the editable scene:
   `blender -b --python tools/blender/build_ranger_source.py`
2. Render all 8 directions × 4 states:
   `blender -b assets/heroes/ranger/source/ranger_source.blend --python tools/blender/render_hero.py -- --config assets/heroes/ranger/source/render_config.json`
3. Pack every state/direction into its own deterministic grid atlas:
   `blender -b assets/heroes/ranger/source/ranger_source.blend --python tools/blender/pack_hero_atlases.py -- --manifest assets/heroes/ranger/renders/ranger_manifest.json`
4. Run structural validation:
   `python tools/validate_hero_assets.py assets/heroes/ranger/renders/ranger_manifest.json`

The renderer maps the configured source-timeline projectile release frame to the nearest rendered frame index, so the manifest event index refers to the sampled animation array. The atlas packer writes unrotated, untrimmed frame rectangles with full source dimensions and uses compact float arrays to limit peak memory.


## Automated Blender build

A GitHub Actions workflow is available at `.github/workflows/ranger-assets.yml`. Run it manually from Actions (or let relevant pipeline changes trigger it). It installs Blender, syntax-checks all scripts, runs the pure-Python packer/validator unit tests, builds the editable scene, validates rig/actions/mesh parenting/materials, renders the complete 8-direction × 4-state set, packs atlases, validates the final manifest and uploads the generated `.blend`, PNG and JSON files as a 14-day workflow artifact. A successful workflow is the first reproducible machine validation gate; it does not replace visual review or Android integration tests.

The artifact is uploaded even when a validation step fails, so a red run still supplies the frames that the failure report refers to.

## Action completeness and pose isolation

Every Action keys every pose bone at every key time. Blender only evaluates the F-curves that exist in the active Action, so a channel that exists only in one Action (for example the `root` rotation that tips the Ranger over in `Ranger_Death`) would otherwise survive an Action switch and deform every later state. `render_hero.py` additionally clears all pose channels before each Action is evaluated. This is what keeps idle/walk/attack upright; a renderer that assigns Actions without resetting the pose will silently produce a toppled character.

## Measured framing and pivot

`orthographic_scale` in `render_config.json` is a **minimum**: the renderer evaluates every sampled pose, projects the union bounds through all eight orbit directions, and widens the scale if any pose would cross the configured margins. `pivot_margin` (default `0.02`) is the normalized clearance kept on every edge.

The `ground_anchor` world point (default `[0, 0, 0]`, the ground under the rig) is pinned to the manifest `pivot` for every direction, and the renderer fails if the projected anchor is more than 0.5% of a frame away from the configured pivot. The stored pivot therefore describes where the feet actually land, for all eight directions and all four states. Do not hand-tune `orthographic_scale` to fix clipping: clipping means a pose exceeds the canvas, and the measured fit is the gate that proves it does not.

The camera is positioned by measuring where the ground anchor currently projects and then sliding it parallel to the image plane (never along the view axis) until the anchor lands on the pivot. Sliding along the view axis would leave the projection unchanged on paper but push the rig behind the orthographic view plane, where Blender clips it and renders a sliver instead of the character. The renderer therefore also fails when any pose corner is less than 0.5 units in front of the camera.

## Death pose and ground clamp

`Ranger_Death` is a forward topple with a short settle. Because the rig rotates around the feet, a falling pose can drive the hood, a shoulder or the quiver below `z = 0`; that would force the measured fit to reserve most of the frame for geometry under the floor and shrink every other state. `build_ranger_source.py` therefore measures the evaluated mesh bounds at every sampled death frame and keys a root-bone translation along world +Z so the lowest point rests exactly on the ground, then re-measures and reports the result (`GROUND_CLAMP ...`).
